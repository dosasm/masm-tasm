# Unified Action Configuration Specification v1

> **Purpose:** Provides a unified data structure definition for action configurations in `dosasm.jsonc` (project-level) and `package.json` (global-level), resolving issues with multiple bundles, `copyFileAs: null`, missing `open` commands, and directory filtering in the current implementation.

---

## 1. Scope

This specification applies to the following two configuration contexts:

| Context | Configuration File | Location |
|---------|-------------------|----------|
| Project-level | `dosasm.jsonc` | Project directory (any depth, searched upward) |
| Global-level | `package.json` → `contributes.configuration.properties["masmtasm.ASM.actions"]` | VSCode user/workspace settings |

Both contexts share the same **Action object** structure (see §2), but differ in default behavior and bundle resolution strategy (see §4).

---

## 2. UnifiedAction Object

### 2.1 Definition

```typescript
interface UnifiedAction {

  // ── Command Sections ────────────────────
  /** Environment setup commands (mount, PATH, etc.). Executed before run/debug. */
  before?: string[];
  /** Commands executed only when opening the emulator */
  open?: string[];
  /** Run commands (required) */
  run: string[];
  /** Debug commands (required) */
  debug: string[];

  // ── File Handling ───────────────────────
  /**
   * Controls whether the active file is copied before run/debug, and specifies its path under DOS.
   * The program parses mount commands from `before` to determine the final DOS location of this file.
   * Different emulators may behave differently at the underlying level, but the effect under DOS is similar.
   * - `null` or `undefined`: Do not copy explicitly; rely on `before` mount commands to make the original file accessible
   * - String: Copy the active file to the specified path (relative to the action directory), and map it to a DOS drive path based on the mount commands in `before`
   *    - dosbox(-x): Copy to ${seperateSpaceFolder}/${copyFileAs}; DOS path is determined by the mount d command
   *    - jsdos(-x): Copy to ./code/${copyFileAs}; DOS path is fixed as D:\${copyFileAs}
   */
  copyFileAs?: string | null;

  // ── Emulator Compatibility ──────────────
  /** Supported emulator list, e.g. ["jsdos", "jsdos-x"] */
  support?: string[];

  // ── Directory Filtering (dosasm.jsonc only) ─
  /** Glob patterns to ignore when injecting the action directory into the bundle. Defaults to ignoring `node_modules`, `.git`, `.vscode`, etc.
   * Only takes effect in jsdos mode (jsdos cannot mount directly; files must be copied into its filesystem, so filtering avoids copying redundant files).
   */
  ignore?: string[];

  // ── Command Overrides ───────────────────
  /** Conditionally override command sections by emulator. When a `when` condition matches, the override fields replace the corresponding fields in the base action. */
  overwrite?: OverWrite[];
}
```

### 2.2 Field Constraints

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `before` | `string[]` | No | `[]` | Environment setup commands (mount, PATH, etc.). **No default auto-mounting; must be explicitly defined** |
| `open` | `string[]` | No | `[]` | Commands executed only when opening the emulator |
| `run` | `string[]` | **Yes** | — | Run commands |
| `debug` | `string[]` | **Yes** | — | Debug commands |
| `copyFileAs` | `string \| null` | No | `undefined` (equivalent to default copy) | File copy control. `undefined` uses the default filename; `null` means no copy |
| `support` | `string[]` | No | `undefined` | Emulator whitelist |
| `ignore` | `string[]` | No | `["node_modules", ".git", ".vscode"]` | Directory filtering (dosasm.jsonc only) |
| `overwrite` | `OverWrite[]` | No | `[]` | Conditional command overrides |

### 2.3 OverWrite Type

```typescript
interface OverWrite {
  /** Match condition; currently supports the `emulator` field */
  when: {
    emulator: string;
  };
  /** Overridden environment setup commands */
  before?: string[];
  /** Overridden open-emulator-only commands */
  open?: string[];
  /** Overridden run commands */
  run?: string[];
  /** Overridden debug commands */
  debug?: string[];
  /** Overridden file copy control */
  copyFileAs?: string | null;
}
```

## 3. Template Variables

The following variables can be used in all command strings (`before` / `open` / `run` / `debug`), expanded at runtime:

| Variable | Meaning | Example |
|----------|---------|---------|
| `${file}` | Full path of the assembly file in DOS | `D:\test.asm` |
| `${filename}` | File name in DOS without extension | `D:\test` |
| `${filefolder}` | Parent directory in DOS without extension | `D:\` |
| `${fileDisk}` | Drive letter in DOS | `D` |
| `${fileOS}` | Full path of the assembly file in the real OS | `D:\Document\test.asm` |
| `${fileOSname}` | File name in the real OS without extension | `D:\Document\test` |
| `${fileOSfolder}` | Parent directory in the real OS without extension | `D:\Document\` |
| `${actionFolder}` | Directory containing dosasm.jsonc (jsdos mode: `./action`) | `./action` |
| `${<built-in>/xxx.jsdos}` | Built-in bundle path; `xxx` is the local bundle name (e.g. `TASM`). In jsdos mode, automatically extracted to the corresponding drive directory; in DOSBox mode, the actual path after extraction. |
| `${https://...}` / `${http://...}` | Network zip package URL. Equivalent to `${<built-in>/...}`; writing the URL directly is more concise. In jsdos mode, automatically downloaded and extracted to the corresponding drive directory; in DOSBox mode, the temporary file path after download. |
| `${logfile}` | Only effective in DOSBox mode. Dynamically generated log file path at runtime (`C:\<random suffix>.log`), used to redirect command output to a log file for diagnostic capture. DOSBox-X uses the `-log-con` parameter to capture from stderr and does not depend on this variable. | `C:\12345678.log` |
| `${seperateSpaceFolder}` | D: drive mount target directory. In jsdos mode: `./code` (virtual directory); in DOSBox mode: temporary workspace directory created by the plugin under `globalStorageUri` (`…/workspace`). | jsdos: `./code`; DOSBox: `C:\Users\...\workspace` |

### 3.1 `>` Prefix Syntax (Removed)

In v1, the `>` prefix no longer has any special semantics. If a historical configuration contains a `>` prefix, the parser automatically strips this character and treats the remaining content as a normal command.

## 4. Contextual Behavior Differences

### 4.1 package.json (Single-file Mode / Global-level)

| Feature | Behavior |
|---------|----------|
| **Bundle** | The `baseBundle` / `bundles` fields are no longer used. Bundle references are entirely embedded via `${<built-in>/...}` in commands, collected and deduplicated at runtime, then loaded. |
| **Mounting** | Entirely controlled by `before` commands. No auto-mounting is performed; users must explicitly define all mounts in `before`. |
| **File Copying** | By default copies to `TEST.<EXT>` (DOSBox, uppercase) or `test.<ext>` (jsdos, lowercase) in the isolated directory. `copyFileAs` can override the target filename. |
| **`open` Commands** | Supported. Previously missing in single-file mode; now added in v1. |
| **`ignore`** | Not applicable (action directory is not traversed). |
| **`support`** | Used for filtering in the status bar assembler selector. |

### 4.2 dosasm.jsonc (Project-level)

| Feature | Behavior |
|---------|----------|
| **Mounting** | Entirely controlled by `before` commands. If `before` is empty, no mounting is performed. |
| **File Copying** | Controlled by `copyFileAs`. When `null`, the file is not injected; rely on mount commands to make the original file accessible. |
| **`open` Commands** | Supported. |
| **`ignore`** | Used to filter subdirectories when injecting the action directory into the bundle (e.g. `node_modules`). |
| **`support` | Optional; used for project-level emulator compatibility declaration. |

## 5. Unified `copyFileAs` Semantics

v1 clarifies the semantics of `copyFileAs`, resolving the issue where files were not injected when `null`.

The core purpose of `copyFileAs` is to copy the active file to a path under DOS. The program automatically parses mount commands from `before` to determine the final DOS location of this file. Different emulators may behave differently at the underlying level, but the effect under DOS is similar.

| Value | jsdos Mode | DOSBox Mode |
|-------|-----------|-------------|
| `undefined` (field absent) | Injects with default filename `test.<ext>` into `code/`; DOS path is `D:\test.<ext>` | Copies with default filename `TEST.<EXT>` to `${seperateSpaceFolder}/`; DOS path is determined by the mount d command |
| `null` | Does not inject the file. `fileInJsdos` is set to `D:\\<original filename>`, relying on `before` mount commands to make the original file accessible | Does not copy to the isolated directory. `fileUri` uses the original path, relying on `mount` commands to override. |
| String (e.g. `"flash.asm"`) | Injects the file into `code/<string>`, `fileInJsdos` = `D:\\<string>` | Copies to `<string>` within the isolated directory; DOS path is determined by the mount d command |

> **Note:** When `copyFileAs: null`, the file must reside in the action directory (or a mounted subdirectory of it); otherwise it will be inaccessible inside the emulator. It is recommended to use `mount d ${actionFolder}` in `before` to ensure accessibility.

## 6. `overwrite` Override Mechanism

When the same action profile needs differentiated commands for different emulators, use the `overwrite` array. At runtime, conditions are matched in order; the first matching entry merges its fields onto the base action (only fields explicitly declared in the override entry are replaced; undeclared fields retain their original values).

### 6.1 Matching Rules

| Condition Field | Description |
|-----------------|-------------|
| `emulator` | Emulator identifier; current valid values: `jsdos`, `jsdos-x`, `dosbox`, `dosbox-x` |

### 6.2 Example

The following configuration automatically appends `${logfile}` redirection in `dosbox` mode; other emulators use the base commands:

```jsonc
{
    "action": {
        "run": [
            "TASM ${file}",
            "TLINK ${filename}",
            "${filename}"
        ],
        "debug": [
            "TASM /zi ${file}",
            "TLINK /v/3 ${filename}.obj",
            "TD -cTDCONFIG.TD ${filename}.exe"
        ],
        "overwrite": [
            {
                "when": { "emulator": "dosbox" },
                "run": [
                    "TASM ${file} > ${logfile}",
                    "TLINK ${filename} >> ${logfile}",
                    "${filename}"
                ],
                "debug": [
                    "TASM /zi ${file} > ${logfile}",
                    "TLINK /v/3 ${filename}.obj >> ${logfile}",
                    "copy C:\\TASM\\TDC2.TD TDCONFIG.TD",
                    "TD -cTDCONFIG.TD ${filename}.exe"
                ]
            }
        ]
    }
}
```

## 7. Implementation Checklist

When implementing the v1 specification, the following behaviors should be ensured:

- [ ] **Multi-bundle loading**: The `baseBundle` + `bundles` properties are completely removed; bundle references are entirely embedded via `${<built-in>/...}` in commands, collected and deduplicated at runtime, then loaded.
- [ ] **`open` command support**: In single-file mode, `getCommands(ActionType.open, null)` returns `action.open ?? []`.
- [ ] **`copyFileAs: null` reliability**: File path derivation accounts for side effects of mount commands (DOSBox) and action folder injection (jsdos).
- [ ] **`ignore` filtering**: `addFolderToJszip` skips directories matching `ignore` glob patterns.
- [ ] **`before` optional**: No default auto-mounting is provided; all mount operations must be explicitly defined by the user in `before`.
- [ ] **`getAction()` exception handling**: When the assembler is undefined, provide a friendly error instead of crashing.
- [ ] **`findDosasmConfig()` URI comparison**: Use normalized URI comparison (trailing-slash aware).
- [ ] **`overwrite` merging**: Match by `when.emulator`, then merge field by field; undeclared fields retain their original values.

## 8. Complete Examples

### 8.1 dosasm.jsonc (Multi-file Project)

```jsonc
{
    "action": {
        "before": [
            "mount c ${<built-in>/TASM.jsdos}",
            "mount d ${actionFolder}",
            "PATH %PATH%;C:\\TASM",
            "d:",
            "cd d:\\"
        ],
        "open": [
            "echo Project: ${actionFolder}"
        ],
        "run": [
            "TASM ${file}",
            "TLINK ${filename}",
            "${filename}"
        ],
        "debug": [
            "TASM /zi ${file}",
            "TLINK /v/3 ${filename}.obj",
            "copy C:\\TASM\\TDC2.TD TDCONFIG.TD",
            "TD -cTDCONFIG.TD ${filename}.exe"
        ],
        "copyFileAs": null,
        "support": ["jsdos", "jsdos-x", "dosbox", "dosbox-x"],
        "overwrite": [
            {
                "when": {
                    "emulator": "dosbox"
                },
                "run": [
                    "TASM ${file} > ${logfile}",
                    "TLINK ${filename} >> ${logfile}",
                    "${filename}"
                ],
                "debug": [
                    "TASM /zi ${file} > ${logfile}",
                    "TLINK /v/3 ${filename}.obj >> ${logfile}",
                    "copy C:\\TASM\\TDC2.TD TDCONFIG.TD",
                    "TD -cTDCONFIG.TD ${filename}.exe"
                ]
            }
        ]
    }
}
```

## Appendix A: Version Changelog

### Changes from Previous Versions to v1

| Change Item | Previous Version | v1 |
|-------------|------------------|----|
| `baseBundle` / `bundles` | Standalone fields configuring the bundle list | **Removed**; bundle references are entirely embedded in commands via `${<built-in>/...}` |
| `open` commands | Missing in package.json mode | **Added**; supported in both contexts |
| `copyFileAs: null` | Ambiguous behavior; files might not be injected | **Semantics clarified**: no copy; rely on mount commands to make the original file accessible |
| `>` prefix | Special syntax suppressing output capture | **Removed**; automatically stripped, no special semantics |
| `overwrite` | Misspelled as `overwirte`, no formal definition | **Formally defined** `OverWrite` type, merged by `when.emulator` matching |
| `ignore` default | Inconsistent | Unified to `["node_modules", ".git", ".vscode"]` |
| Directory filtering description | Confused jsdos/DOSBox applicability | Clarified that it only takes effect in jsdos mode (jsdos cannot mount; files must be copied) |
| Default auto-mounting | package.json auto `mount c .` + `mount d ./code`; dosasm.jsonc empty `before` falls back to default mounting | **Completely removed**; all mounting must be explicitly defined by the user in `before` |
| DOSBox log capture | `insertLOGFLE` automatically appends `>>C:\\xxx.log` to commands | **Changed to overwrite mechanism**: default profiles include a `dosbox` overwrite entry, using the `${logfile}` variable for log redirection |
| DOSBox-X log capture | Does not rely on `${logfile}`; uses `-log-con` parameter | **Unchanged**; DOSBox-X does not use `${logfile}`; overwrite only covers `dosbox` |
| `${seperateSpaceFolder}` variable | None; D: drive mount target hardcoded to `./code` | **New template variable**; resolves to `./code` in jsdos mode and `globalStorageUri/workspace` in DOSBox mode |

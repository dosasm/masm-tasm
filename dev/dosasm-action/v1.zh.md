# Unified Action Configuration Specification v1

> 目的：为 `dosasm.jsonc`（项目级）和 `package.json`（全局级）中的 action 配置提供统一的数据结构定义，解决当前实现中的多 bundle、`copyFileAs: null`、`open` 命令缺失、目录过滤等问题。

---

## 1. 适用范围

本规范适用于以下两个配置上下文：

| 上下文 | 配置文件 | 路径 |
|--------|---------|------|
| 项目级 | `dosasm.jsonc` | 项目目录（任意层级，向上搜索） |
| 全局级 | `package.json` → `contributes.configuration.properties["masmtasm.ASM.actions"]` | VSCode 用户/工作区设置 |

两个上下文共享同一套 **Action 对象** 结构（见 §2），但在默认行为和 bundle 解析策略上有所不同（见 §4）。

---

## 2. UnifiedAction 对象

### 2.1 定义

```typescript
interface UnifiedAction {

  // ── 命令段 ──────────────────────────────
  /** 环境准备命令（挂载、PATH 等）。在 run/debug 前执行。*/
  before?: string[];
  /** 仅打开模拟器时执行的命令 */
  open?: string[];
  /** 运行命令（必填） */
  run: string[];
  /** 调试命令（必填） */
  debug: string[];

  // ── 文件处理 ────────────────────────────
  /**
   * 控制是否在运行/调试前复制活动文件，并指定其在 DOS 下的路径。
   * 程序会从 `before` 命令中解析 mount 指令，确定该文件在 DOS 中的最终位置。
   * 不同 emulator 的底层行为可能不同，但在 DOS 下的效果类似。
   * - `null` 或 `undefined`：不显式复制，依赖 `before` 中的 mount 命令使原文件可访问
   * - 字符串：将活动文件复制到指定路径（相对于 action 目录），并根据 `before` 中的 mount 命令映射到 DOS 盘符路径
   *    - dosbox(-x) 时复制到 ${seperateSpaceFolder}/${copyFileAs}，DOS 路径由 mount d 命令确定
   *    - jsdos(-x) 时复制到 ./code/${copyFileAs}，DOS 路径固定为 D:\${copyFileAs}
   */
  copyFileAs?: string | null;

  // ── 模拟器兼容性 ─────────────────────────
  /** 支持的模拟器列表，如 ["jsdos", "jsdos-x"] */
  support?: string[];

  // ── 目录过滤（仅 dosasm.jsonc） ──────────
  /** 在将 action 目录注入 bundle 时要忽略的 glob 模式。默认忽略 `node_modules`、`.git`、`.vscode` 等文件夹。
   * 仅 jsdos 模式下生效（jsdos 无法直接 mount，只能复制文件到其文件系统中，为避免复制冗余文件而过滤）。
   */
  ignore?: string[];

  // ── 命令覆盖 ────────────────────────────
  /** 按模拟器条件覆盖部分命令段。匹配 `when` 条件后，使用覆盖值替换对应字段。 */
  overwrite?: OverWrite[];
}
```

### 2.2 字段约束

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `before` | `string[]` | 否 | `[]` | 环境准备命令（挂载、PATH 等）。**不再有默认自动挂载，必须显式定义** |
| `open` | `string[]` | 否 | `[]` | 仅打开模拟器时执行 |
| `run` | `string[]` | **是** | — | 运行命令 |
| `debug` | `string[]` | **是** | — | 调试命令 |
| `copyFileAs` | `string \| null` | 否 | `undefined`（等效于默认复制） | 文件复制控制。`undefined` 时使用默认文件名；`null` 时不复制 |
| `support` | `string[]` | 否 | `undefined` | 模拟器白名单 |
| `ignore` | `string[]` | 否 | `["node_modules", ".git", ".vscode"]` | 目录过滤（仅 dosasm.jsonc） |
| `overwrite` | `OverWrite[]` | 否 | `[]` | 按条件覆盖命令 |

### 2.3 OverWrite 类型

```typescript
interface OverWrite {
  /** 匹配条件，当前支持 `emulator` 字段 */
  when: {
    emulator: string;
  };
  /** 覆盖的环境准备命令 */
  before?: string[];
  /** 覆盖的仅打开模拟器命令 */
  open?: string[];
  /** 覆盖的运行命令 */
  run?: string[];
  /** 覆盖的调试命令 */
  debug?: string[];
  /** 覆盖的文件复制控制 */
  copyFileAs?: string | null;
}
```

## 3. 模板变量

所有命令字符串（`before` / `open` / `run` / `debug`）中均可使用以下变量，由运行时展开：

| 变量 | 含义 | 示例 |
|------|------|------|
| `${file}` | 汇编文件在 DOS 中的完整路径 | `D:\test.asm` |
| `${filename}` | 去掉扩展名 DOS 中的文件名 | `D:\test` |
| `${filefolder}` | 去掉扩展名 DOS 中的父目录 | `D:\` |
| `${fileDisk}` | 去掉扩展名 DOS 中的磁盘名 | `D` |
| `${fileOS}` | 汇编文件在 真实OS 中的完整路径  | `D:\Document\test.asm` |
| `${fileOSname}` | 去掉扩展名 真实OS 中的文件名 | `D:\Document\test` |
| `${fileOSfolder}` | 去掉扩展名 真实OS 中的父目录  | `D:\Document\` |
| `${actionFolder}` | dosasm.jsonc 所在目录（jsdos 模式下为 `./action`） | `./action` |
| `${<built-in>/xxx.jsdos}` | 内置 bundle 的路径，`xxx` 为本地 bundle 名（如 `TASM`）。jsdos 模式下自动解压到对应驱动目录；DOSBox 模式下为解压后的实际路径 |
| `${https://...}` / `${http://...}` | 网络 zip 包 URL。与 `${<built-in>/...}` 等效，直接写 URL 更简洁。jsdos 模式下自动下载并解压到对应驱动目录；DOSBox 模式下为下载后的临时文件路径 |
| `${logfile}` | 仅在 DOSBox 模式下生效。运行时动态生成的日志文件路径（`C:\<随机后缀>.log`），用于将命令输出重定向到日志文件以供诊断捕获。DOSBox-X 使用 `-log-con` 参数从 stderr 捕获，不依赖此变量 | `C:\12345678.log` |
| `${seperateSpaceFolder}` | D: 盘挂载目标目录。jsdos 模式下为 `./code`（虚拟目录）；DOSBox 模式下为插件在 `globalStorageUri` 下创建的临时工作目录（`…/workspace`） | jsdos: `./code`；DOSBox: `C:\Users\...\workspace` |

### 3.1 `>` 前缀语法（已移除）

v1 中 `>` 前缀不再具有任何特殊语义。若历史配置中包含 `>` 前缀，程序在解析时会自动剥离该字符，将其后的内容作为普通命令执行。

## 4. 上下文行为差异

### 4.1 package.json（单文件模式 / 全局级）

| 特性 | 行为 |
|------|------|
| **bundle** | 不再使用 `baseBundle` / `bundles` 字段。bundle 引用完全通过命令中的 `${<built-in>/...}` 内嵌，由运行时收集并去重后加载 |
| **挂载** | 完全由 `before` 命令控制。不再自动执行任何挂载操作，必须由用户在 `before` 中显式定义 |
| **文件复制** | 默认复制到隔离目录下的 `TEST.<EXT>`（DOSBox 大写）或 `test.<ext>`（jsdos 小写）。`copyFileAs` 可覆盖目标文件名 |
| **`open` 命令** | 支持。单文件模式下之前缺失，v1 补充 |
| **`ignore`** | 不适用（不遍历 action 目录） |
| **`support`** | 用于状态栏 assembler 选择器过滤 |

### 4.2 dosasm.jsonc（项目级）

| 特性 | 行为 |
|------|------|
| **挂载** | 完全由 `before` 命令控制。若 `before` 为空，不执行任何挂载操作 |
| **文件复制** | 由 `copyFileAs` 控制。`null` 时不注入文件，依赖 mount 使原文件可访问 |
| **`open` 命令** | 支持 |
| **`ignore`** | 用于在将 action 目录注入 bundle 时过滤子目录（如 `node_modules`） |
| **`support`** | 可选，用于项目级模拟器兼容性声明 |

## 5. `copyFileAs` 语义统一

v1 对 `copyFileAs` 的语义做了明确界定，解决了 `null` 时文件未注入的问题。

`copyFileAs` 的核心作用是将活动文件复制到 DOS 下的某个路径。程序会自动从 `before` 命令中解析 mount 指令，确定该文件在 DOS 中的最终位置。不同 emulator 的底层行为可能不同，但在 DOS 下的效果类似。

| 值 | jsdos 模式 | DOSBox 模式 |
|----|-----------|-------------|
| `undefined`（字段缺失） | 使用默认文件名 `test.<ext>` 注入到 `code/`，DOS 路径为 `D:\test.<ext>` | 使用默认文件名 `TEST.<EXT>` 复制到 `${seperateSpaceFolder}/`，DOS 路径由 mount d 命令确定 |
| `null` | 不注入文件。`fileInJsdos` 设为 `D:\\<原始文件名>`，依赖 `before` 中的 mount 命令使原文件可访问 | 不复制到隔离目录。`fileUri` 使用原始路径，依赖 `mount` 命令覆盖 |
| 字符串（如 `"flash.asm"`） | 注入文件到 `code/<字符串>`，`fileInJsdos` = `D:\\<字符串>` | 复制到隔离目录下的 `<字符串>`，DOS 路径由 mount d 命令确定 |

> **注意**：`copyFileAs: null` 时，文件必须位于 action 目录（或其挂载子目录）中，否则模拟器内无法访问。建议在 `before` 中使用 `mount d ${actionFolder}` 确保可访问性。

## 6. `overwrite` 覆盖机制

当同一个 action profile 需要为不同模拟器提供差异化命令时，使用 `overwrite` 数组。运行时按顺序匹配 `when` 条件，第一个命中的条目将其字段合并到基础 action 上（仅覆盖条目中显式声明的字段，未声明的保持原值）。

### 6.1 匹配规则

| 条件字段 | 说明 |
|---------|------|
| `emulator` | 模拟器标识符，当前可选值：`jsdos`、`jsdos-x`、`dosbox`、`dosbox-x` |

### 6.2 示例

以下配置在 `dosbox` 模式下自动追加 `${logfile}` 重定向，其他模拟器使用基础命令：

```jsonc
{
    "action": {
        "run": [
            "TASM ${file}",
            "TLINK ${filename}",
            "${filename}"
        ],
        "debug": [
            "TASM /zi ${file}",
            "TLINK /v/3 ${filename}.obj",
            "TD -cTDCONFIG.TD ${filename}.exe"
        ],
        "overwrite": [
            {
                "when": { "emulator": "dosbox" },
                "run": [
                    "TASM ${file} > ${logfile}",
                    "TLINK ${filename} >> ${logfile}",
                    "${filename}"
                ],
                "debug": [
                    "TASM /zi ${file} > ${logfile}",
                    "TLINK /v/3 ${filename}.obj >> ${logfile}",
                    "copy C:\\TASM\\TDC2.TD TDCONFIG.TD",
                    "TD -cTDCONFIG.TD ${filename}.exe"
                ]
            }
        ]
    }
}
```

## 7. 实现检查清单

在实现 v1 规范时，应确保以下行为：

- [ ] **多 bundle 加载**：`baseBundle` + `bundles` 属性已完全删除，bundle 引用全部通过命令内嵌的 `${<built-in>/...}` 完成，运行时收集并去重后加载
- [ ] **`open` 命令支持**：单文件模式下 `getCommands(ActionType.open, null)` 返回 `action.open ?? []`
- [ ] **`copyFileAs: null` 可靠性**：文件路径推导考虑 mount 命令的副作用（DOSBox）和 action folder 注入（jsdos）
- [ ] **`ignore` 过滤**：`addFolderToJszip` 跳过匹配 `ignore` glob 的目录
- [ ] **`before` 可选**：不再提供默认自动挂载，所有挂载操作必须由用户在 `before` 中显式定义
- [ ] **`getAction()` 异常处理**：assembler 未定义时给出友好错误而非崩溃
- [ ] **`findDosasmConfig()` URI 比较**：使用标准化 URI 比较（尾部斜杠感知）
- [ ] **`overwrite` 合并**：按 `when.emulator` 匹配后逐字段合并，未声明字段保留原值

## 8. 完整示例

### 8.1 dosasm.jsonc（多文件项目）

```jsonc
{
    "action": {
        "before": [
            "mount c ${<built-in>/TASM.jsdos}",
            "mount d ${actionFolder}",
            "PATH %PATH%;C:\\TASM",
            "d:",
            "cd d:\\"
        ],
        "open": [
            "echo Project: ${actionFolder}"
        ],
        "run": [
            "TASM ${file}",
            "TLINK ${filename}",
            "${filename}"
        ],
        "debug": [
            "TASM /zi ${file}",
            "TLINK /v/3 ${filename}.obj",
            "copy C:\\TASM\\TDC2.TD TDCONFIG.TD",
            "TD -cTDCONFIG.TD ${filename}.exe"
        ],
        "copyFileAs": null,
        "support": ["jsdos", "jsdos-x", "dosbox", "dosbox-x"],
        "overwrite": [
            {
                "when": {
                    "emulator": "dosbox"
                },
                "run": [
                    "TASM ${file} > ${logfile}",
                    "TLINK ${filename} >> ${logfile}",
                    "${filename}"
                ],
                "debug": [
                    "TASM /zi ${file} > ${logfile}",
                    "TLINK /v/3 ${filename}.obj >> ${logfile}",
                    "copy C:\\TASM\\TDC2.TD TDCONFIG.TD",
                    "TD -cTDCONFIG.TD ${filename}.exe"
                ]
            }
        ]
    }
}
```

## 附录 A：版本变更说明

### v1 相比之前版本的变化

| 变更项 | 旧版 | v1 |
|--------|------|----|
| `baseBundle` / `bundles` | 独立字段，配置 bundle 列表 | **已删除**，bundle 引用全部内嵌在命令的 `${<built-in>/...}` 中 |
| `open` 命令 | package.json 模式下缺失 | **新增**，两种上下文均支持 |
| `copyFileAs: null` | 行为不明确，文件可能未注入 | **语义明确**：不复制，依赖 mount 使原文件可访问 |
| `>` 前缀 | 特殊语法，抑制输出捕获 | **已删除**，自动剥离，无特殊语义 |
| `overwrite` | 拼写为 `overwirte`，无正式定义 | **正式定义** `OverWrite` 类型，按 `when.emulator` 匹配合并 |
| `ignore` 默认值 | 不统一 | 统一为 `["node_modules", ".git", ".vscode"]` |
| 目录过滤说明 | 混淆 jsdos/DOSBox 适用场景 | 明确仅 jsdos 模式生效（因为 jsdos 无法 mount，只能复制文件） |
| 默认自动挂载 | package.json 自动 `mount c .` + `mount d ./code`；dosasm.jsonc 空 `before` 回退默认挂载 | **完全删除**，所有挂载必须由用户在 `before` 中显式定义 |
| DOSBox 日志捕获 | `insertLOGFLE` 自动追加 `>>C:\\xxx.log` 到命令 | **改为 overwrite 机制**：默认 profile 中内置 `dosbox` 的 overwrite 条目，通过 `${logfile}` 变量实现日志重定向 |
| DOSBox-X 日志捕获 | 不依赖 `${logfile}`，使用 `-log-con` 参数 | **保持不变**，DOSBox-X 不使用 `${logfile}`，overwrite 仅覆盖 `dosbox` |
| `${seperateSpaceFolder}` 变量 | 无，D: 盘挂载目标硬编码为 `./code` | **新增**模板变量，jsdos 下解析为 `./code`，DOSBox 下解析为 `globalStorageUri/workspace` |
